# 使用示例：总经理工作模式

本文件是按需资源。老板（用户）不需要读它——它给「接到任务、准备启动团队的 Agent」看：怎么触发、怎么调参、什么场景合适。

## 怎么下达任务

最自然的一句话即可，不需要背参数：

```
用总经理工作模式：帮我做一份智能家居行业的竞品分析报告
```

```
让总经理团队做一套社区奶茶店的开业方案，包括选址分析、产品定价和开业活动策划
```

```
你只当老板，剩下的交给总经理——把这份用户访谈整理成一份产品需求文档 + 一份 30 天排期
```

## 调参数

参数由老板在下达时随口指定，不指定就用默认：

| 参数 | 默认 | 范围 | 怎么说 |
| --- | --- | --- | --- |
| `maxWorkers` | 6 | 2–6 | 「拆成 3 个工作包就行」 / 「最多 4 个人」 |
| `maxRounds` | 2 | ≥1 | 「审核严格点，返工最多 3 轮」 / 「别返工了，一轮过就行」 |

示例：

```
用总经理团队做一份同城生鲜配送的市场调研，最多 4 个工作包，返工上限 3 轮。
```

任务很小（例如只写一段文案）时不必动用团队——每个员工都是一次完整的智能体会话，任务越大越划算。

## 典型场景

| 场景 | 总经理大概会怎么拆 |
| --- | --- |
| 行业/竞品/市场分析报告 | 资料搜集员 · 竞品分析员 · 数据校验员 · 结论汇总（GM 自己） |
| 商业计划 / 活动策划 | 背景调研 · 方案主体 · 预算与数据 · 风险审查 |
| 系列内容生产 | 选题大纲 · 正文撰写 ×N · 配图/素材清单 · 统一校对 |
| 软件功能开发 | 需求细化 · 前端 · 后端 · 测试用例（各自自验，GM 查衔接） |
| 数据整理流水线 | 采集 · 清洗 · 分析 · 可视化说明 |

## 你会看到什么（有进度能力时）

- 阶段播报：拆解分工 → 员工并行执行 → 总经理审核 → 打回返工 → 独立审读 → 汇总交付。
- 工作包看板：每个员工实时状态（执行中 / 待审核 / 返工中 / 已通过 / 未达标）。
- 成果文件：工作区里每个工作包一份独立 Markdown，随时点开细看。
- 最终交付：《总经理交付报告》——任务结论、各部分成果与文件位置、遗留问题。

## 不适合的场景

- 「帮我把这句话润色一下」——一句话能答，拆包反而更慢。
- 「我们聊聊这个方向靠不靠谱」——用户要的是讨论，不是交付物。
- 「按我说的第一步、第二步做」——用户明确要主对话逐步推进。
- 需要**实时人机来回确认每一步**的任务——团队模式偏「交钥匙」，中间只在关键决策请示老板。

## 质量与诚实性约定（对老板的说明）

- 三道关：员工自验 → 总经理逐包打开成果文件验收、不合格打回 → 独立审读员冷读最终报告。
- 到达返工上限仍未达标的部分，报告里会如实标注「未完全达标」并列入遗留问题，不粉饰。
- 没有任务无关的自动化校验门（编译/测试等），由员工自行验证、总经理把关；审读员是抽查，不是逐字校验。
- 交付报告结尾注明「AI 辅助生成，重要信息请自行核实」。

## 跨会话复用（可选）

如果运行环境有「项目记忆 / 团队档案」，可以把上次任务的成果目录与结论存下来，下次同类任务让总经理先读一遍再规划。这不是本 skill 的必需步骤，没有记忆能力时跳过。
